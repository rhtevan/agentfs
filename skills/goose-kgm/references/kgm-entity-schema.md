# KGM Entity Schema

> Version: 1.0.0
> Used by: `reindex-kgm.sh`
> Format: JSONL (one JSON object per line)

## Entity Types

### KnowledgeBundle

Represents an OKF knowledge bundle directory.

```json
{
  "type": "entity",
  "name": "bundle:<bundle-display-name>",
  "entityType": "KnowledgeBundle",
  "observations": [
    "Source: <absolute-path>/index.md",
    "Summary: <description-from-knowledge-index>"
  ]
}
```

**Naming:** `bundle:` prefix + display name from knowledge index
(e.g., `bundle:Skupper V2 Concepts`).

### KnowledgeConcept

Represents a single concept document within a bundle.

```json
{
  "type": "entity",
  "name": "concept:<bundle-name>/<concept-display-name>",
  "entityType": "KnowledgeConcept",
  "observations": [
    "Source: <absolute-path>/<concept-file>.md",
    "Summary: <description-from-bundle-index>",
    "Bundle: <bundle-display-name>"
  ]
}
```

**Naming:** `concept:` prefix + bundle name + `/` + concept display
name (e.g., `concept:Skupper V2 Concepts/Site and Link Resources`).

## Relation Types

### contains

Bundle → Concept relationship.

```json
{
  "type": "relation",
  "from": "bundle:<bundle-name>",
  "to": "concept:<bundle-name>/<concept-name>",
  "relationType": "contains"
}
```

Every concept has exactly one `contains` relation from its parent
bundle.

## Observation Conventions

| Observation Prefix | Purpose | Present On |
|--------------------|---------|------------|
| `Source:` | Absolute file path — the agent reads this file | Both |
| `Summary:` | Short description for search relevance | Both |
| `Bundle:` | Parent bundle name for grouping | Concept only |

## Discovery Flow

1. Agent calls `search_nodes("<query>")` with a topic keyword
2. KGM returns matching entities with their observations
3. Agent reads `Source:` observation to get the file path
4. Agent reads the actual file for full content

This replaces the multi-hop walk:
`knowledge/index.md` → find bundle → `bundle/index.md` → find concept → read file

With a single deterministic call:
`search_nodes("skupper")` → `Source: ~/.agents/knowledge/skupper-v2-concepts/site-link-resources.md`

## Schema Constraints

- Entity names are **deterministic** — same input produces same name
- No cross-bundle `related_to` relations in v1.0 (future enhancement)
- Tags are not indexed in v1.0 — `Summary` and entity names provide
  sufficient search surface for `search_nodes` substring matching
- Absolute paths in `Source:` observations — resolved at reindex time
