# MOIM / Persistent Instructions — Architecture Reality

Goose's MOIM (Model-Observed Internal Memory) provides persistent
instructions via `GOOSE_MOIM_MESSAGE_FILE`. Understanding the actual
delivery mechanism is critical for SOUL.md identity delivery.

## Architecture (Source-Code Verified)

Two separate mechanisms share the "MOIM" name:

### 1. `{{ moim_system_prompt_block }}` in system.md

`moim::system_prompt_block()` in `prompt_manager.rs` returns a
**hardcoded explanation template** — the "# Turn Context" text that
tells the model what `<turn-context>` blocks are. This is always
rendered regardless of the tom extension. It has nothing to do with
`instructions.md` or SOUL.md.

### 2. tom (Top Of Mind) extension — `get_moim()`

The `tom` platform extension in `platform_extensions/tom.rs` reads
`GOOSE_MOIM_MESSAGE_FILE` (instructions.md) and returns its content
via the `get_moim()` MCP trait method. This content is collected by
`lease.moim()` in `moim.rs` and composed into a `<turn-context>`
block — a **user-role message** injected **every turn** at the
**recency peak**.

## Key Facts

| Property | Value |
|----------|-------|
| Source file | `~/.config/goose/instructions.md` |
| Reader | tom extension `get_moim()` |
| Delivery | Per-turn `<turn-context>` user message |
| Position | **Recency peak** (last content before model generates) |
| Requires | `tom` extension `enabled: true` in config.yaml |
| Without tom | Content never reaches the model — zero delivery |

## What {{ moim_system_prompt_block }} Actually Is

It is NOT instructions.md content. It is a hardcoded Goose platform
text explaining what `<turn-context>` blocks are:

```
# Turn Context

Each turn may include a `<turn-context>` block added to the request.
This block is generated by goose and contains current operational context...
```

This renders in the system prompt (primacy zone) always, regardless
of tom extension state. Moving its position in system.md has no
effect on SOUL delivery.

## Consequence for AgentFS

- **tom extension is a hard dependency** for SOUL.md delivery on Goose
- Without tom, weaker models (14B) confabulate identity principles
  (0/9 correct). With tom, they cite them accurately (9/9 correct)
- `system-md-gen.sh --generate` auto-enables tom and checks its status
- `instructions.md` is the source file for SOUL content. Profile
  switching (`activate-profile.sh`) overwrites the SOUL section there
